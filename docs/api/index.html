MochaSession

Top-level entry point. One session per app process. Manages the QUIC connection to the relay (via picoquic on native, WebTransport on web), token refresh, automatic reconnection, LAN relay fallback, and the lifecycle of all open channels.

Defined in mocha.udl · Implemented in mocha-core/src/session.rs
constructorthrows MochaError
MochaSession(config: SessionConfig)
Creates a session, opens the QUIC connection to the relay, and performs the MOQT setup handshake. Blocks until connected or throws. Call from a background thread. On internet loss, automatically falls back to an mDNS-discovered LAN relay if enable_lan_relay is true.

MochaChannel

Represents one channel, DM, or group DM. Obtained via session.join_channel() or session.join_dm(). Manages message pub/sub, file transfer, presence, reactions, receipts, and threads — all over MoQ tracks. Thread-safe; safe to call from any thread.

Defined in mocha.udl · Implemented in mocha-core/src/channel.rs
asyncthrows MochaError
send(content: String, options: SendOptions?) → Message
Optimistically appends the message to local SQLite (immediately visible in UI via on_message), then publishes to the MoQ track. The returned Message.is_pending is true until the relay assigns a stable group/object ID. If offline, the message is queued in the WAL and delivered on reconnect.

options.mentionsList<String>? optionalUser IDs to @mention; triggers push notification

MochaHuddle

Ephemeral audio/video room. Audio and video are published as separate MoQ tracks per device. An ephemeral MLS group is created for E2E-encrypted media signalling. Destroyed when all participants leave.

Defined in mocha.udl · Implemented in mocha-core/src/huddle.rs

LocalStore

Read-only view into the local SQLite cache. All methods are synchronous and never touch the network. Obtained via session.store(). Backed by a WAL-mode read-only connection pool — safe to call from any thread without blocking the QUIC event loop.

Defined in mocha.udl · Implemented in mocha-core/src/storage/store.rs

MochaIdentity

The authenticated identity bound to this session and device. Returned by MochaSession.identity(). The user_id is a stable hashed value derived from the MOAT v2 credential — it does not change across sessions or devices for the same account. The device_id is unique per device and stored in the system Keychain (iOS/macOS) or Keystore (Android).

Defined in mocha.udl

display_nameStringHuman-readable name set during account creation or SSO import.
device_idStringPer-device stable ID stored in Keychain/Keystore. Used to scope MoQ tracks to this device (hDevId in track names).

enum
AuthMode

Selects the token provider used to mint relay access tokens. Set once in SessionConfig.auth_mode. The relay validates the token on every publish/subscribe — no token, no access. NoAuth is only accepted by relays explicitly configured for debug mode.

Defined in mocha.udl
VariantToken typeIdentity linkageRequired config
Cat CWT/COSE-signed Common Access Token (IETF draft-ietf-avtcore-cat) Linked — token contains hashed user ID. Suitable for authenticated users. moat_url required
PrivacyPass Blind-signed Privacy Pass token (RFC 9576). Issuer cannot link token to the redemption request. Unlinkable — IP not associated with identity. Suitable for privacy-sensitive publishing. moat_url + pp_issuer_url required
NoAuth No token. Connection accepted unconditionally. None — open access. Relay must have auth = none in config. Debug/testing only.

Attachment

A reference to a file published as a MoQ track. Files never pass through a server — they are chunked and published directly on the relay as binary objects on a file_v1_<sha256> track. Call MochaChannel.upload() to get an Attachment, then pass it in SendOptions.attachments. Recipients call MochaChannel.download(content_hash) to retrieve the bytes.

mime_typeStringMIME type (e.g. image/png, application/pdf). Used by the UI for preview rendering.
