MOAT v2
Only place with RDBMS
Citus
Horizontal sharding
Design rule: Messages, files, and presence live in the MoQ relay (not in these databases). These schemas cover only what requires persistent, queryable, server-side storage: identity, membership, permissions, metadata, compliance archive, and recording. The relay is the message store; the database is the record of truth about who can access what.

message_db — Message Archive & Compliance
Written by the Recording Server which subscribes to all MoQ message tracks. Primary store is still the relay. This DB enables compliance export, eDiscovery, full-text search at scale, and long-term retention beyond relay TTL.
Important: Messages here are written asynchronously by the archive subscriber — not in the send path. Relay delivery is still sub-200ms; DB write latency does not affect users.

fts messages_content_fts — GIN tsvector on content (pg_trgm)
Show full-text search index 
-- Full-text search over archived messages
ALTER TABLE messages
    ADD COLUMN content_fts tsvector
    GENERATED ALWAYS AS (to_tsvector('english', coalesce(content, ''))) STORED;

CREATE INDEX messages_fts_idx ON messages USING GIN (content_fts);

-- Example search query
SELECT id, channel_id, sender_id, sent_at,
       ts_headline('english', content, query) AS snippet
FROM messages,
     to_tsquery('english', 'design & review') query
WHERE content_fts @@ query
  AND channel_id = '...'
ORDER BY ts_rank(content_fts, query) DESC
LIMIT 20;

recording_db — Recording Server
The Recording Server subscribes to all MoQ tracks in a huddle (or channel), stitches objects into segments, stores them in S3, and serves playback via HTTP Range requests or a MoQ replay track.
MoQ Relay                Recording Server              Clients / Playback

media_audio_dev1 ──────►  Subscribe all tracks  ──► stitch segments
media_video_dev1 ──────►  Decode + mux (ffmpeg)     ──► S3 upload
media_screen_dev2 ─────►  Update recording_db        ──► signed URL
msg_v2_dev1 ───────────►  Archive messages ───────────► HTTP GET /recordings/{id}
                                                         or MoQ replay track

Show monthly partitioning DDL 
CREATE TABLE audit_log (
    id          uuid        NOT NULL DEFAULT gen_random_uuid(),
    org_id      uuid        NOT NULL,
    actor_id    uuid,
    actor_ip    inet,
    action      text        NOT NULL,
    target_type text,
    target_id   text,
    metadata    jsonb,
    occurred_at timestamptz NOT NULL DEFAULT now()
) PARTITION BY RANGE (occurred_at);

-- Monthly partitions created by a cron job
CREATE TABLE audit_log_2026_07
    PARTITION OF audit_log
    FOR VALUES FROM ('2026-07-01') TO ('2026-08-01');

-- Old partitions detached and exported to S3 as Parquet for long-term storage
ALTER TABLE audit_log DETACH PARTITION audit_log_2025_01;
-- → COPY audit_log_2025_01 TO 's3://mocha-audit/2025/01/' (FORMAT PARQUET)
